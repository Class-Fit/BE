# 공공데이터 동기화 운영 검증

## 자동 실행 정책

정기 동기화는 기본적으로 비활성화한다. 시설·강좌 API 설정과 전체 수동 동기화를 검증한 환경에서만 다음 값을 설정한다.

```text
PUBLIC_DATA_SYNC_ENABLED=true
```

기본 실행 시각은 `Asia/Seoul` 기준 매일 03:00이다. 운영 환경에서는 `PUBLIC_DATA_SYNC_CRON`, `PUBLIC_DATA_SYNC_ZONE`으로 변경할 수 있다.

## 2026-09-28 로컬 검증 결과

상위 `.env`에 설정된 API 주소와 인증키를 실행 프로세스에 주입해 검증했다. 인증키와 인증키가 포함된 요청 URL은 기록하지 않았다.

### API smoke test

- 시설 API 응답: `resultCode=00`, `NORMAL SERVICE`
- 강원 시설 총건수: 969건
- 시설 필수 식별자 `brno`, `facil_sn` 확인
- 시설 응답의 식별자로 강좌 API 호출 성공
- 강좌 API 응답: HTTP 200, `resultCode=00`
- 실제 강좌 3건이 있는 시설에서 `course_no`, `course_nm` 확인

### 전체 수동 동기화

- 실행 진입점: `CourseSyncService.syncGangwonCourses()`
- 처리 시설: 969건
- 처리 강좌: 2,176건
- Gradle 검증 작업 전체 시간: 6분 25초
- 동기화 테스트 메서드 실행 시간: 약 6분 14초
- 실행 전 DB: 시설 969건, 강좌 2,176건
- 실행 후 DB: 시설 969건, 강좌 2,176건
- `(brno, facil_sn)` 중복 시설: 0건
- `(facility_id, course_no)` 중복 강좌: 0건

시설 API의 `pageSize`가 1,000이고 전체 시설이 969건이므로 시설 요청은 1회 발생한다. 현재 구현은 시설마다 강좌 API를 최소 한 번 호출하므로 이번 데이터 기준 전체 동기화는 최소 970회의 외부 요청을 사용한다. 강좌가 1,000건을 넘는 시설이 있으면 추가 페이지 요청이 발생한다.

## 제공기관 정책 확인

- [강좌 API 공공데이터포털 공개 페이지](https://www.data.go.kr/data/15107784/openapi.do)는 개발계정 한도를 일 10,000회로 안내한다.
- 운영계정은 활용사례 등록 후 트래픽 증가를 신청할 수 있다고 안내한다.
- 시설 API의 과거 데이터셋 상세 페이지는 현재 정상적인 상세 정보를 반환하지 않아 공개 페이지에서 호출 한도를 재확인하지 못했다.
- 두 API의 데이터 갱신 주기는 공개 상세 페이지에서 확인되지 않았다.

시설 API 한도와 실제 데이터 갱신 주기는 공공데이터포털의 활용신청 상세 또는 제공기관 문의로 확인한 뒤 이 문서를 갱신한다. 확인 전에는 전체 동기화를 하루 한 번보다 자주 실행하지 않는다.

## 재검증 절차

1. 시설 API 1페이지의 HTTP 상태, `resultCode`, `totalCount`를 확인한다.
2. 반환된 시설 하나의 `brno`, `facil_sn`으로 강좌 API를 호출한다.
3. 전체 수동 동기화를 실행한다.
4. 실행 전후 시설·강좌 건수와 유니크 키 중복 건수를 비교한다.
5. 오류 응답과 로그에 인증키 또는 인증키가 포함된 전체 URL이 없는지 확인한다.
6. 검증이 끝난 환경에서만 정기 동기화를 활성화한다.
